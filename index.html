TRANSPARENT BY DESIGN

How it works

A small local check to help developers catch common accidental credential exposures.

01

Files stay on your device

Your browser reads the files you select and scans their text in memory. The app makes no network requests for file content and has no upload endpoint, account, or storage.

Private by architecture: no matched value is rendered, saved, or written to the CSV report.
02

Pattern-based detection

Six rules look for private-key markers, common provider token formats, and credential-like assignments. Assignment matches use a length and character-diversity heuristic.

03

Bounded working-tree scan

The scan checks up to 5,000 files, 1 MB per file, and 50 MB total. It skips common generated and dependency directories, binary files, oversized files, and Git history.

04

Review, then rotate

Findings include the path, line, detector, severity, and a suggested response. If a real credential has been committed, remove it from the repository and rotate it with the provider.

!

Know the limits

This is a lightweight heuristic, not a replacement for Gitleaks, TruffleHog, GitHub Secret Scanning, or a security review. It does not scan Git history, binaries, ignored folders, remote repositories, or every provider format. False positives and missed secrets are possible. A match does not establish that a credential is active; a clean result does not establish that a repository is safe.

Reviewed status is kept only in the current page session. The downloadable CSV contains finding metadata and remediation guidance, but no secret values.
